# alerts-check

Проверка файла `alerts.yaml` — описания того, что в проекте считать поломкой.
В репозитории ровно две вещи: схема формата (`alerts.schema.json`) и действие
GitHub, которое по ней проверяет конфиг.

## Подключение

В `.github/workflows/alerts.yml` репозитория:

```yaml
      - uses: actions/checkout@v5
      - uses: Smolevich/alerts-check@v1
```

Токен не нужен, репозиторий может быть чей угодно. По умолчанию проверяется
`alerts.yaml` в корне; другой путь — входом `config`.

Сломанный конфиг валит сборку и называет строку и причину:

```
alerts.yaml:22: поле «таймаут» схеме неизвестно — опечатка?
```

## Версии

`@v1` — последняя схема первой версии: правила в ней только смягчаются, ранее
правильный конфиг от неё не покраснеет. Строгое закрепление — полный номер,
например `@v1.0.0`; он не двигается никогда.

Номер версии схемы лежит в ней самой (`x-версия`) и печатается в лог сборки —
видно, чем именно проверяли.

## Откуда это берётся

Содержимое собирается автоматически из закрытого источника и сюда только
приезжает. Правки, сделанные здесь руками, затираются следующей публикацией.
